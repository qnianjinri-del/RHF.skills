# LEGAL / 归属与整合策略

## 当前策略

本仓库当前采用 **reference-first** 模式：

- 记录上游仓库信息
- 保留外链和证据链接
- 不默认复制上游全文
- 不默认内嵌 prompts / tools / SKILL.md 原文

这样做是为了尽量降低：

- 许可证不兼容
- 归属遗漏
- 上游仓库更新后出现漂移
- 多个同构项目互相覆盖

## 什么时候才考虑 vendor / submodule

只有在以下条件尽量明确时才建议推进：

1. LICENSE 明确存在且兼容
2. README 或仓库说明没有额外限制
3. 保留原作者、原仓库、原许可证信息
4. 明确记录是镜像、子模块还是再分发副本

## 当前建议

- `inspected` 不等于可以直接 vendoring
- `candidate_unverified` 更不应该直接复制内容
- 首阶段最稳妥的公开发布方式，就是当前这种聚合索引仓
